# The Cut — working notes

Personal training and nutrition log for a 21-week cut (Aug–Dec 2026). Offline-first
PWA, no backend, no accounts, no analytics.

- Repo: `sanirb-debug/fitnesstracker` — Pages serves `main` / root
- Live: https://sanirb-debug.github.io/fitnesstracker/

The app is named "The Cut"; the repo is `fitnesstracker`. Nothing in the app depends
on the repo name — every asset path is relative — but the boot test's `BASE` and the
URLs in this file do, so update them if the repo is ever renamed.

**The app is written and working. Read the source before changing it.** Most of the
rules below exist because breaking them silently destroys logged data rather than
throwing an error.

## Layout

```
src/App.jsx            the entire app (~2,900 lines) — source of truth
src/entry.jsx          mounts <App/> into #root via react-dom/client
app.js                 BUILT OUTPUT — never edit by hand, regenerated by the build
index.html             page shell, install metadata, safe-area handling
sw.js                  service worker (offline cache)
manifest.webmanifest   install metadata
.nojekyll              empty, but required
icon-*.png, favicon.png, apple-touch-icon.png
scripts/bump-sw.mjs    bumps the SW cache version
scripts/boot-test.mjs  headless jsdom boot test
```

Built output lives at the repo root because Pages serves from `main` / root.

## Build

```bash
npm run build     # esbuild only
npm run release   # bump SW cache version, then build  ← use this before deploying
npm test          # headless boot test (run after a build)
```

The build is exactly:

```bash
npx esbuild src/entry.jsx --bundle --minify --format=iife \
  --loader:.jsx=jsx --jsx=automatic --target=es2019 \
  --define:process.env.NODE_ENV='"production"' \
  --outfile=app.js
```

Produces a ~705KB `app.js`. `--target=es2019` is deliberate — this runs on a phone.
Don't raise it.

Note the quoting on `--define`. It must reach esbuild as the *string* `"production"`.
If it arrives as a bare identifier, React's dev branches survive, the bundle jumps to
~1.1MB, and you ship a dev build. In `package.json` that means `'\"production\"'`.
Check the bundle size after touching the build script.

## The two-target Store adapter

The same source runs in two places:

- **Inside a Claude artifact** — persistence goes through `window.storage`
- **On the self-hosted site** — persistence goes through `localStorage`

`Store` (near the top of `src/App.jsx`) detects which exists and exposes one async
`get`/`set` interface. Don't break that split, and **don't remove `localStorage`.**
Claude artifacts ban `localStorage`, and that rule is easy to apply from memory here
by mistake — it does not apply to a self-hosted site. On the web build `localStorage`
is the only thing making persistence work.

## Storage keys — never rename

```
hollandcut:v1          main state
hollandcut:photos:v1   progress photos
hollandcut:aikey       optional Anthropic API key
hollandcut:probe       write/read probe
```

There is real logged data under these. Renaming one silently orphans it.

## Hard constraints

**Paths must be relative.** This serves from a project subpath
(`https://sanirb-debug.github.io/fitnesstracker/`), not a root domain. Every reference
in `index.html`, `manifest.webmanifest` and `sw.js` must be `./app.js`, not `/app.js`
— including `start_url` and `scope`. Absolute paths 404. The boot test catches this.

**Keep `.nojekyll`.** Without it GitHub runs Jekyll over the site and can drop files.
It's empty; make sure it survives every commit.

**Bump the SW cache on every deploy.** `const CACHE = "the-cut-v1"` → `v2` → … .
Otherwise installed phones keep serving the stale build. `npm run release` does it.

**Use `clone()`, not bare `structuredClone`.** `clone()` (top of `src/App.jsx`) falls
back to a JSON round-trip. Unguarded `structuredClone` crashed on older Safari and
every log tap threw.

**Don't cache API calls in the service worker.** `sw.js` explicitly skips
`anthropic.com`. Keep that.

**No secrets in the repo.** The Anthropic API key is optional, entered at runtime in
Settings, and held in `localStorage`. Never hardcode, commit, or write it to a config
file. `.gitignore` covers `node_modules/`, `.env*`, `.DS_Store`.

**Preserve the iPhone safe-area CSS.** The `.hc` / `.hcnav` / `.hcpad` rules and
`env(safe-area-inset-*)` keep the bottom nav off the home bar in standalone mode.

**`Sheet` must stay portalled to `<body>`, wrapped in a `.hc` host.** Two traps,
both silent:

- Each tab renders inside a `.rise` wrapper, and the `hcrise` animation settles on
  an *identity matrix* rather than `transform:none`. That is still enough to make
  the wrapper the containing block for `position:fixed` children — so a sheet
  rendered in place sizes itself to the tab, not the viewport, and hangs off the
  bottom of the screen with its last controls cut off.
- Portalling to `<body>` escapes the app root, where every design token
  (`--card`, `--ink`, `--rule`) and the `.hc input` rules live. Without a
  `className="hc"` wrapper on the portal, the sheet renders completely unstyled.

The wrapper zeroes `.hc`'s own page layout (`minHeight`, `background`,
`paddingTop`) so it paints nothing itself.

**Walks are `type:"walk"`, not `type:"run"`.** `weekMiles`, the plan bar, the
per-day dots and the stats totals all filter on `type === "run"`, so a walk typed
as a run silently counts walking miles toward the week's running target. A
treadmill *run* is still `type:"run"` and still counts — only `surface`
(`outside` | `treadmill`) differs. `EditWorkout` treats anything with `miles` as
distance-shaped, so walks get the distance/pace fields for free.

**Never declare a component inside another component's render.** `NumField` sits
at module level for this reason. Declared inside `EditWorkout` it becomes a new
component type on every render, so React unmounts and remounts the input on each
keystroke — the field loses focus and the phone keyboard closes after one
character, and values typed into a stale node are silently dropped. Build helpers
from plain functions returning JSX (as `EditWorkout`'s `Num()` does) or hoist
them out.

## Verification gates

Don't call a change done until these pass:

1. Build exits clean; `app.js` exists and is >500KB (expect ~705KB).
2. Serve locally (`npm run serve`) and `curl -sI` → `200` for `/index.html`,
   `/app.js`, `/manifest.webmanifest`, `/sw.js`, `/icon-192.png`.
3. `npm test` — headless jsdom boot at the real Pages origin (`BASE` in the test)
   with `window.storage` deleted, asserting: `#boot` gets replaced, text contains
   "On the board today", no `NaN`/`undefined` rendered, the Greek Yogurt Power Bowl
   quick-log writes a `hollandcut` key containing the meal name, and a remount with
   that storage still shows it.
4. After deploy: `curl -sI` the live URL → `200`, live `app.js` non-empty. Pages can
   take a couple of minutes on first publish — poll, don't assume.

Fix failures rather than lowering the assertions.

The boot test blocks every request outside the project path, which is how it catches
absolute paths. The Google Fonts `@import` in the app's CSS is the one expected
off-base request — it's progressive enhancement with a `system-ui` fallback, and
`sw.js` caches it separately.

## Notes

- `recharts` is the only heavy dependency. If bundle size ever becomes a problem it's
  the thing to replace with hand-rolled SVG — but don't, without asking.
- Deliberately offline-first and serverless. Don't add a backend, accounts, or analytics.
- `node_modules` isn't needed to deploy — only `app.js` and the static files at root.
